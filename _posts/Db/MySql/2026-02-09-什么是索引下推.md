索引下推是 MySQL 在 5.6 版本中（于2013年2月5日发布）引入的一种优化技术，用于提高查询性能。它的主要作用是将部分 `WHERE` 条件下推到存储引擎层，在扫描索引时尽可能过滤掉不符合条件的记录，从而减少回表次数和数据传输量。

# 工作原理
在没有索引下推之前，MySQL 的查询执行流程如下：
1. 存储引擎根据索引条件扫描索引，找到满足索引条件的记录。
2. 存储引擎将记录的主键或行号返回给 MySQL Server 层。
3. MySQL Server 层根据主键回表读取完整的行数据。
4. MySQL Server 层应用 `WHERE` 条件过滤数据。

在有索引下推之后，流程优化为：
1. 存储引擎根据索引条件扫描索引。
2. 存储引擎在扫描索引时直接应用部分 `WHERE` 条件，过滤掉不符合条件的记录。
3. 只有符合条件的记录才会返回给 MySQL Server 层，减少了回表次数和数据传输量。

# 索引下推的优势
1. **减少回表次数**：
    - 如果索引中包含了部分查询条件，存储引擎可以直接过滤掉不符合条件的记录，避免不必要的回表操作。
2. **降低数据传输量**：
    - 存储引擎只将符合条件的记录返回给 MySQL Server 层，减少了数据传输的开销。
3. **提高查询性能**：
    - 通过减少回表和数据传输，查询性能显著提升。

# 索引下推的适用场景
索引下推主要适用于以下场景：
1. **复合索引**：
    - 当查询条件中包含复合索引的部分字段时，存储引擎可以利用索引下推优化。
2. **范围查询**：
    - 对索引字段进行范围查询（如 `<`、`>`、`BETWEEN`）时，索引下推可以减少回表次数。
3. **部分字段过滤**：
    - 如果 `WHERE` 条件中的某些字段在索引中，存储引擎可以直接过滤这些字段。

# 索引下推的限制
1. **单列索引**：
    - 如果查询条件只涉及单列索引，索引下推的效果有限。
2. **未使用索引的字段**：
    - 如果 `WHERE` 条件中的字段未包含在索引中，索引下推无法优化这些条件。
3. **函数或表达式**：
    - 如果查询条件对索引字段使用了函数或表达式（如 `LEFT(column, 3) = 'abc'`），索引下推无法生效。

# 示例
假设有一个表 `t_book_question_mapping`，包含以下字段和索引：
```
CREATE TABLE t_book_question_mapping (
    id INT PRIMARY KEY,
    book_num_id INT,
    area_type INT,
    question_id VARCHAR(255),
    INDEX idx_book_area (book_num_id, area_type)
);
```
## 查询语句
```
SELECT * 
FROM t_book_question_mapping 
WHERE book_num_id = 50052627 AND area_type = 1003;
```

## 无索引下推
- 存储引擎扫描索引 `idx_book_area`，找到所有 `book_num_id = 50052627` 的记录。因为在5.6版以前的存储引擎，对索引优化的能力相对有限，一般只要找到`where`条件中第一个满足索引规则的字段后就不在继续向后查找。这也就是为什么符合索引中完全包括`where`子句中所列的字段但依旧会发生大量回表。
- 将这些记录的主键返回给 MySQL Server 层。
- MySQL Server 层回表读取完整行数据，并应用 `area_type = 1003` 的过滤条件。

## 有索引下推
- 存储引擎扫描索引 `idx_book_area`，同时应用 `book_num_id = 50052627` 和 `area_type = 1003` 的条件。
- 只有符合条件的记录才会返回给 MySQL Server 层，减少了回表次数。
